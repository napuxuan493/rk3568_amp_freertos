## 二、M2.2 的核心工作量：把 FreeRTOS AArch64 port 从 GICv2 适配到 GICv3

`freertos-kernel/portable/GCC/ARM_CA53_64_BIT`（V10.6.2）是为 GICv2 写的
（CPU 接口走 MMIO GICC），RK3568 是 GICv3（CPU 接口 = ICC_*_EL1 系统寄存器）。
适配点：

| 文件 | 改动 |
|---|---|
| portASM.S | ① ack：`LDR W0,[ICCIAR]` → `MRS X0, s3_0_c12_c12_0`(ICC_IAR1_EL1) ② eoi → `MSR s3_0_c12_c12_1, X0`(ICC_EOIR1_EL1) ③ portSAVE_CONTEXT 的 PMR 写 → `MSR s3_0_c4_c6_0, X1`(ICC_PMR_EL1)；FreeRTOS_Abort → 跳我们的 abort_handler |
| port.c | ① portCLEAR_INTERRUPT_MASK/uxPortSetInterruptMask/FreeRTOS_Tick_Handler 的 PMR → ICC_PMR_EL1 ② BPR 校验 → ICC_BPR1_EL1 ③ 优先级检查偏移 0x400→0x420（GICD_IPRIORITYR8）④ RPR 校验 → ICC_RPR_EL1 |
| portmacro.h | 保留（ICC* 宏不再使用，靠 port.c 直接改） |
| 编译标志 | 必须 `-DGUEST`（port 在 EL1 运行；否则它读 SPSR_EL3 会 trap） |

## 三、踩坑记录（每个都是真实的调试课）

1. **binutils 2.36 不认 `icc_*_el1` 寄存器名** → 必须用 `s3_0_...` 编码
   （ICC_PMR_EL1=s3_0_c4_c6_0, ICC_IAR1_EL1=s3_0_c12_c12_0, ICC_EOIR1_EL1=s3_0_c12_c12_1,
    ICC_BPR1_EL1=s3_0_c12_c12_3, ICC_SRE_EL1=s3_0_c12_c12_5, ICC_IGRPEN1_EL1=s3_0_c12_c12_7,
    ICC_RPR_EL1=s3_0_c12_c11_3）

2. **GIC 只有 4 位优先级（16 级）**：写 0xFF 到 GICD_IPRIORITYR8 读回 0xF0
   → configUNIQUE_INTERRUPT_PRIORITIES 必须是 16（不是 256）
   → vPortValidateInterruptPriority 的 `while((v&1)!=1) v>>=1` 在 v=0 时死循环

3. **GICv3 下 GICD_IPRIORITYR0 恒为 0**：SGI/PPI 优先级在重分发器里，
   分发器的 R0-R7（INTID 0-31）是 RES0 → port 的优先级检查要改读 GICD_IPRIORITYR8（0x420）

4. **tick PPI = INTID 30**（= dts GIC_PPI 14 = CNTP 非安全物理定时器）：
   - 内核跑 VHE(EL2) 时 CNTP_EL1 重定向到 CNTHP_EL2 → INTID 26（/proc/interrupts 所见）
   - 我们在 EL1 用 CNTP_EL0 不重定向 → INTID 30
   - 使能全部 PPI 16-31 时启动期会先排空 ~14 个 pending（各触发一次），之后 30 持续重复
   - **教训**：单 PPI 20 测试失败是"排空噪声误导"，靠"全 PPI + 统计重复"才定位

5. **"core1 死在内核启动前"是误诊**：其实是 tick 停止（PPI 配错）→ 任务全冻结在
   vTaskDelay → 看起来像死了。tick 恢复后任务全程存活（无 cpuidle 杀核）

6. **向量表路由**：同步异常槽 → FreeRTOS_SWI_Handler（SVC yield 用），
   IRQ 槽 → FreeRTOS_IRQ_Handler，FIQ/SError → abort_handler（打印 ESR/FAR/ELR/SP）
   —— SVC 槽指错会直接 [EXC]（esr=0x56000000）

## 四、工程文件

- core1/FreeRTOSConfig.h（16 优先级、静态分配、configSETUP/CLEAR_TICK_INTERRUPT）
- core1/gic.c（GICv3 最小初始化：GICD+GICR+PPI30+ICC_*）
- core1/timer.c（CNTP_EL0：TVAL 装填 + CTL 使能）
- core1/main.c（2 任务 + vApplicationIRQHandler + idle 内存）
- core1/startup.S（向量表：SWI/IRQ/abort 路由）
- core1/crash.c（异常诊断打印）
- core1/libc_min.c（memset/memcpy 等，-nostdlib 需要）
- freertos-kernel/portable/GCC/ARM_CA53_64_BIT/{port.c,portASM.S}（GICv3 适配）

## 五、遗留（M3 前可清理）
- 当前 gic.c 只配 PPI 30（干净）；amp.its data-size=0x10000 足够（core1.bin 36KB）
- u-boot 对 "core1-freertos" 的 sysmem 保留只有 64KB（data-size），
  我们的栈延伸到了 0x7016150 > 0x7010000 —— M3 建议把 data-size 调大到覆盖整个镜像+栈
  （或把保留区对齐到 1MB 的 core1-fw）
