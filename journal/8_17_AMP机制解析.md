## 读完了什么（结合 8_16~8_17 对话总结）

**文件一：`rockchip-mailbox.c`（drivers/mailbox/，318 行）——通道提供方（controller）**
- 寄存器宏（L17~25）：A2B/B2A 两组 × INTEN/STATUS/CMD/DAT，通道 i 的偏移 = 0x08+8i / 0x30+8i
- `mbox_chan_ops`（L114）：send_data（同步写 A2B）/ startup（使能 B2A 中断）/ shutdown / last_tx_done（轮询 busy 位）
- `rockchip_mbox_irq`（L140）：收路径——读 STATUS → 逐通道匹配 → 读 8 字节 → `mbox_chan_received_data` 交付 → **W1C 清位（电平触发必须清，否则中断风暴）**
- probe（L181）：devm 分配（kzalloc 单结构 / kcalloc 数组+防溢出）、`platform_get_irq` 循环（`-ENXIO` = 共享中断复用 0 号）、`devm_request_threaded_irq`（NULL handler + IRQF_ONESHOT）、`goto disable_clk` 单一出口错误处理（devm 兜底，只手动还时钟使能态）
- compatible 家族复用：`"rockchip,rk3368-mailbox"` 服务 rk3568/rk3588/rk3528/rk3562（dts 双 compatible：specific + fallback）
- 发送路径**无中断**：同步写寄存器；完成检测靠 `txdone_poll`（dts 可配 `rockchip,txpoll-period-ms`，默认 5ms，板子配 1ms）
- 触发机制：中断判断在硅片（STATUS&INTEN 与门），软件只做开闸（INTEN）/收件/回执（W1C）
- `devm_kzalloc vs kcalloc`：kcalloc 防 n×size 溢出；devm = 自动释放（`.remove()` 都可以不写）

**文件二：`rockchip_rpmsg.c`（drivers/rpmsg/，414 行）——virtio master + mailbox 客户端**
- 两层架构：**控制面 = mailbox 8 字节门铃**（cmd=link_id + data="RMSG" 魔数），**数据面 = vring 共享内存**
- `rk_rpmsg_notify`（L80）：kick 回调——**奇数 queue_id = 发队列每次敲门；偶数 = 收队列仅 `first_notify` 握手一次，之后 return true 忽略**
- `rk_rpmsg_find_vq`（L115）：ioremap vring 物理地址 → `vring_new_virtqueue`（同时挂 notify 和 callback）
- `rk_rpmsg_rx_callback`（L58）：B2A 中断 → 验证魔数 → `RPMSG_REMOTE_IS_READY` → `vring_interrupt`
- probe（L291）：`mbox_request_channel_byname` 申请 rx/tx → 读 `rockchip,link-id`（0x03=0核↔3核）/`rockchip,vdev-nums` → `rk_set_vring_phy_buf` 规划 vring → `of_reserved_mem_device_init` 建共享 DMA 池 → 注册多个 virtio 设备
- vring 三件套：**desc 表（数据缓冲描述）/ available ring（生产者=Linux 写）/ used ring（消费者=core1 写）**，idx 是递增游标；`virtio_wmb/mb` 屏障保证"先写数据后亮 idx"
- 空 config_ops（get/set_status/reset）：无状态寄存器，virtio 状态机由 **mailbox 握手替代**
- 内存布局：vring 结构体在 `rpmsg_reserved`（reg 0x7c00000），消息缓冲在 `rpmsg_dma_reserved`（memory-region / shared-dma-pool 0x8000000）

**文件三：`rockchip_amp.c`（drivers/soc/rockchip/，630 行）——core1 启动器 + GIC 分割 + sysfs**
- 电源域保电：`of_count_phandle_with_args` 数 power-domains → 1 个直接 `pm_runtime_resume_and_get`，多个 `dev_pm_domain_attach_by_id` 逐个（runtime PM 只自动绑第一个）——**是保电不是配电**
- 开核：`amp-cpus` 子节点（id/entry/mode/boot-on）→ `sip_smc_amp_config`（**SMC 陷入 EL3 ATF**）→ CPU_ON
- GIC 分割：`amp-irqs = <irq prio aff>` → `amp_ctrl` 表 → GIC 驱动初始化时 `rockchip_amp_get_gic_info`（irq-gic.c L1570）→ 写路由寄存器；Linux 对 `amp_flag=1` 的中断一律 `-EINVAL` 拒绝（irq-gic.c 8 处检查）
- sysfs：`kobject_create_and_add("rk_amp", NULL)` → `boot_cpu` 属性文件（`echo on/off/status 3 > /sys/rk_amp/boot_cpu`）
- `boot_on`：旧 dts 无该属性 → 默认 1（向后兼容自动启动），新 dts 写 `boot-on = <0>` 可按需启动
- "probe 上面的函数没被调用"的真相：static 函数走 sysfs 属性表回调，非 static 函数跨文件导出给 GIC 驱动用

## 三个收获（必须能用自己的话讲）

1. 理解了双核通信的大致流程：控制面（mailbox 门铃）+ 数据面（vring 共享内存）两层分离，**门铃只传信号不传数据，地址是双方固定契约**；发送是同步函数链、接收才用中断。
2. 了解了内存屏障，各种 write 函数的不同之处以及应用场景：`__raw_writel`（裸写）→ `writel_relaxed`（+字节序）→ `writel`（+屏障）；同一设备寄存器之间硬件保序可用 relaxed，**跨「寄存器↔RAM」必须屏障**（M2 写 core1 固件时 dmb 的坑预告）。
3. 理解了设备树中的参数如何通过代码获取：`of_property_*` 系列（read_u32/read_u32_index/count_phandle_with_args/parse_phandle/of_get_child_by_name）+ `device_property_*`（通用）→ `platform_get_irq/resource` 拿中断/寄存器。
4. 理解了驱动的编写就是 platform（of_match_table + probe/remove）和各种框架回调（fops、mbox_chan_ops、virtio_config_ops、rx_callback）相互配合写的。
