## 二、本次修复的两个关键源码 bug

### Bug 1（u-boot）：amp_cpus_on 只读 4KB 头，FIT 稍大就解析失败
- 文件：`u-boot/drivers/cpu/rockchip_amp.c`
- 症状：amp.img ≤ ~3.6KB 能 boot（旧 test_A 3675B 恰好卡在窗口内），≥6.6KB 报 `AMP Error: No totalsize`
- 根因：`amp_cpus_on` 先只读 `FIT_HEADER_SIZE`(4KB)，再 `fit_get_totalsize()` 用 `fdt_getprop(fit, 0, "totalsize")` 查根属性。**属性名在 FDT 字符串块（off_dt_strings）**，对 6.6KB 的 FIT 位于 0x15CC（>4KB）→ libfdt 越界读 → 查不到 → 报错
- 修复：一次性读分区前 4MB（有界，避免 dwmmc 16 位块数上限 0xFFFF=32MB 整分区读失败），字符串块必然在内；加错误打印
- 教训：Rockchip 的 FIT 解析假定 FIT 很小；fdt 属性名查找依赖字符串块，读窗口必须覆盖它

### Bug 2（工具链用法）：parameter.txt 需要 uuid: 行固定 system GUID
- 症状：`di -p` 后 system 分区 GUID 随机（gen_rand_uuid），内核 `root=PARTUUID=614e0000-0000` 前缀匹配失败 → `Waiting for root device`
- 根因：upgrade_tool 对没有 `uuid:` 行的分区随机生成 GUID；官方 rk3588 parameter 就是靠 `uuid:rootfs=614e0000-...` 固定
- 修复：`rockdev/parameter.txt` 追加
  ```
  uuid:system=614e0000-0000-4000-8000-000000000000
  uuid:boot=7A3F0000-0000-446A-8000-702F00006273
  ```
- 验证：`blkid` 显示 p5 system PARTUUID=614e0000-0000-4000-8000-000000000000，p3 boot=7a3f...
- 注意：工具的本地 `GPT` 命令会忽略 uuid 行，但 `di -p`（设备流程）会采纳

## 三、可复现的烧录流程（用户要求：只改源码 + 重烧）

1. **改 parameter.txt** 加 uuid 行（见上）
2. **loader 模式**（按住 RECOVERY 上电）→
   `upgrade_tool di -p rockdev/parameter.txt`（system GUID=614e0000）
   `upgrade_tool di -b kernel/boot.img`（含 amp dts 的 FIT：cpu3 disabled、core1-fw@7000000 no-map 等）
   `upgrade_tool di -uboot rockdev/uboot.img`（CONFIG_AMP=y + 上述 Bug1 修复）
3. **amp.img 烧录**（板内 Linux 操作，免进 loader）：
   `wget http://<PC>:8000/amp.img -O /tmp/amp.img`
   `dd if=/tmp/amp.img of=/dev/mmcblk0p7 bs=512 conv=fsync`
4. 重启验证
